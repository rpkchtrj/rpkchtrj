## 🚧 Current Focus

### Aether

**Building a high-throughput, distributed, fault-tolerant workflow execution engine in Go.**

Aether is my flagship systems project and my primary vehicle for going deeper into
Go, distributed systems, reliability engineering, and performance engineering.

I'm approaching it as more than a software project: the goal is to explore how
distributed execution systems are **designed, implemented, tested, operated,
and reasoned about under failure**.

The project will explore:

- DAG execution and dependency scheduling
- concurrency and backpressure
- execution semantics and state machines
- retries and duplicate execution
- leases, heartbeats, reassignment, and fencing
- durable state and crash recovery
- remote workers and RPC
- distributed coordination
- observability and distributed tracing
- chaos engineering and incident investigation
- benchmarking and performance engineering
- security and trust-boundary analysis

> **The goal is not simply to build a working system.  
> The goal is to understand why it is correct, how it fails, how to recover it,
> and where its guarantees end.**

## 🧠 Engineering Approach

I care about the parts of backend engineering that become difficult when systems stop being simple:

**state → concurrency → failure → recovery → coordination → performance**

I try to approach engineering problems by asking:

- What must always be true?
- Who owns this state?
- What happens when the network lies?
- What happens when a process disappears?
- What survives a restart?
- Can this operation happen twice?
- Where does backpressure go?
- How would we prove this behavior?
- How would we diagnose it at 3 AM?

I also use AI-assisted development deliberately: **AI can reduce typing, but it should not replace engineering judgment.**
